Both are sync engines that keep a local replica in the browser and reconcile it against a server. They disagree about where queries run, how writes are expressed, and what you have to deploy.

This page states what each project's documented default architecture does. Zero is a good piece of engineering, and the last section says plainly when it is the better pick.

## The short answer

Pick **Zero** if you want reactive queries expressed in its own query language, evaluated against a server-side cache, and you are willing to run `zero-cache` next to your database.

Pick **Strata Sync** if you want Linear's architecture: models and decorators in TypeScript, a server-sequenced log, and a sync server that is a route inside your existing Fastify app rather than a separate process.

## Side by side

|                        | Strata Sync                                            | Zero                              |
| ---------------------- | ------------------------------------------------------ | --------------------------------- |
| Backend                | Your Postgres, inside your Fastify app                 | Your Postgres + `zero-cache`      |
| Extra service to run   | None. Optional Redis for fan-out                       | Self-hosted `zero-cache`          |
| Write path             | Built in: durable outbox, `/sync/mutate`               | Custom mutators                   |
| Ordering and conflicts | Server-sequenced log, field-level rebase               | Server-authoritative, rebased     |
| Query model            | Model classes and typed queries over the local replica | ZQL, its own query language       |
| Collaborative text     | Yjs, built in                                          | Bring your own CRDT               |
| Undo and redo          | Built in, from transaction history                     | Bring your own                    |
| Licence                | MIT                                                    | Check the current Zero repository |

## Where the designs actually differ

### The deployment unit

Zero introduces a process. `zero-cache` sits between your client and Postgres, holds the replica the server reasons about, and has to be run, scaled and monitored like any other service.

Strata Sync introduces routes. `@stratasync/server` registers `/sync/bootstrap`, `/sync/mutate` and a WebSocket on the Fastify app you already deploy, and reads the same Postgres you already run. Redis is optional, and only for fan-out across instances.

This is the difference most likely to decide it for you, and it cuts both ways: a separate cache is also a separate thing you can scale independently.

### How you ask for data

Zero ships ZQL, a query language of its own, and queries are subscriptions that update as the underlying data changes.

Strata Sync follows Linear: you declare model classes with `@ClientModel` and `@Property`, and read them back through typed queries and React hooks. Reads hit the local replica, so they are synchronous and do not suspend once a model is loaded. There is no new query language to learn, and no query planner between you and your data.

### How writes are ordered

Both are server-authoritative and both rebase, so neither asks you to reason about CRDT merge semantics for records.

Strata Sync's ordering is the piece it takes most directly from Linear: one monotonic counter, one total order, and a client that catches up after a week offline by asking for everything after a single integer. Conflicts are resolved per field rather than per record, so two people editing different fields of the same row do not collide. See [the sync protocol](/architecture/sync-protocol) and [Linear's sync engine, open-sourced](/architecture/linear-sync-engine).

### Text editing

Server ordering handles records well and text badly. Strata Sync uses Yjs CRDTs for rich text and ships presence with it, so collaborative editing is a package rather than a project. With Zero you bring your own CRDT layer.

## When to pick Zero instead

- You want queries as the primary abstraction and you like ZQL.
- You are happy to run and operate `zero-cache`.
- Your data model is relational rather than object-graph shaped, and you would rather write queries than declare model classes.
- You want the backing of a team whose whole product this is. Strata Sync is one author plus contributors, in production on one product.

Sync engines are a real commitment, so read both sets of docs before choosing. If Linear's architecture is the thing you actually want, that is what this project implements.
